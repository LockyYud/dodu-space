> **Paper**: Corrective Retrieval Augmented Generation
> **Tác giả**: Shi-Qi Yan, Jia-Chen Gu, Yun Zhu, Zhen-Hua Ling
> **Venue**: ICLR 2024 — arXiv:2401.15884
> **Loại**: `engineering_reading_note`

## Thesis

CRAG đáng học không phải vì nó thêm web search vào RAG. Phần quan trọng hơn là **quality gate giữa retrieval và generation**.

RAG production cần biết khi nào context retrieved không đủ tin cậy. Nếu generator luôn bị ép trả lời từ top-k chunks, hệ thống sẽ hallucinate có tổ chức.

## Problem I Care About

Naive RAG thường có shape:

```text
retrieve top-k -> put into prompt -> generate answer
```

Pipeline này giả định top-k đủ tốt. Trong thực tế, top-k có thể:

- irrelevant;
- chỉ liên quan chủ đề nhưng thiếu answer;
- outdated;
- chứa nhiều noise;
- mâu thuẫn nhau;
- không đủ evidence để trả lời.

Nếu không có bước kiểm tra, generator vẫn sẽ trả lời. Đây là nguồn hallucination rất phổ biến.

## The Paper's Core Idea

CRAG thêm một retrieval evaluator. Evaluator chấm relevance giữa query và retrieved documents, rồi chọn một trong ba action:

- **CORRECT**: context đủ tốt, dùng retrieved docs sau khi refine;
- **INCORRECT**: context kém, bỏ retrieved docs và dùng web search;
- **AMBIGUOUS**: context không rõ, kết hợp retrieved docs và web search.

Paper cũng dùng decompose-then-recompose: tách documents thành knowledge strips, lọc phần liên quan, rồi ghép lại context sạch hơn.

## What Actually Matters

Tôi không nghĩ phần "web search" là thứ nên copy nguyên vào mọi hệ thống. Bài học quan trọng hơn:

```text
retrieval result phải được đánh giá trước khi generator dùng nó
```

Quality gate có thể dẫn tới nhiều action khác nhau:

- proceed;
- retrieve thêm;
- rewrite query;
- dùng source khác;
- hỏi clarification;
- từ chối vì thiếu evidence;
- escalate sang human;
- trả lời với uncertainty rõ ràng.

CRAG là một ví dụ cụ thể của tư duy này.

## Implementation Sketch

Version production tối giản tôi sẽ build trước:

```text
1. Hybrid retrieve top-20.
2. Rerank top-20.
3. Compute evidence quality:
   - max relevance score;
   - mean top-3 score;
   - source diversity;
   - contradiction flags;
   - citation coverage.

4. Route:
   - high confidence: answer normally;
   - medium confidence: retrieve more or rewrite query;
   - low confidence: say not enough evidence or fallback to approved source.

5. Log decision and scores.
```

Tôi sẽ chỉ thêm web search nếu domain cho phép web là source đáng tin. Với enterprise docs, fallback tốt hơn có thể là internal search, ticket system, database, hoặc refusal.

## Production Tradeoffs

**Evaluator sai thì pipeline sai**. False positive làm generator nhận context kém. False negative làm hệ thống fallback không cần thiết hoặc từ chối câu có thể trả lời.

**Threshold tuning khó**. Ngưỡng confidence phải được tune theo domain và cost of error. Không nên lấy threshold từ paper.

**Web search không phải universal fallback**. Với nội dung nội bộ, web có thể sai hơn corpus chính.

**Latency tăng**. Evaluator, extra retrieval, context filtering, web calls đều thêm delay.

## When I Would Use It

Tôi sẽ dùng CRAG-like gating khi:

- hallucination cost cao;
- corpus có thể thiếu hoặc outdated;
- user chấp nhận câu "không đủ evidence";
- có nhiều sources để fallback;
- cần citation đáng tin.

Đây là pattern tốt cho legal/internal knowledge/enterprise QA hơn là chatbot demo.

## When I Would Not Use It

Tôi sẽ chưa dùng CRAG đầy đủ khi:

- chưa có eval set để tune evaluator;
- latency cần rất thấp;
- corpus đã nhỏ và curated;
- fallback source không đáng tin;
- app chấp nhận answer approximate.

Khi đó, chỉ cần reranker + refusal rule đơn giản có thể đủ.

## What I Distrust

Tôi không tin giả định "retrieval sai thì web search tốt hơn". Điều này chỉ đúng với một số open-domain questions. Với domain nội bộ, web search có thể đưa hallucination vào bằng đường chính thức.

Tôi cũng muốn thấy evaluator-level precision/recall rõ hơn. Nếu evaluator là module quyết định routing, chất lượng của nó phải được đo riêng, không chỉ đo final QA.

## Experiment I Would Run

Tôi sẽ so:

```text
naive RAG
RAG + reranker
RAG + evaluator gate + refusal
RAG + evaluator gate + query rewrite
CRAG-like fallback to external source
```

Metrics:

- answer correctness;
- citation faithfulness;
- refusal correctness;
- false accept rate;
- false reject rate;
- latency p95;
- fallback rate;
- cost/query.

Với high-stakes domain, false accept quan trọng hơn raw accuracy.

## Takeaway

CRAG nhắc rằng RAG cần biết khi nào không nên trả lời.

Điểm tôi sẽ mang vào production:

- thêm quality gate trước generation;
- đo evaluator như một module riêng;
- fallback phải domain-aware;
- refusal là action hợp lệ;
- context refinement có thể quan trọng ngang retrieval.
