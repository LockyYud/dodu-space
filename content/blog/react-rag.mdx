> **Paper**: ReAct: Synergizing Reasoning and Acting in Language Models
> **Tác giả**: Shunyu Yao, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao
> **Venue**: ICLR 2023 — arXiv:2210.03629
> **Loại**: `engineering_reading_note`

## Thesis

ReAct đáng học vì nó biến RAG từ một pipeline tĩnh thành một loop có hành động: **model có thể suy nghĩ, gọi tool, quan sát kết quả, rồi quyết định bước tiếp theo**.

Nhưng ReAct cũng là điểm bắt đầu của nhiều agent quá phức tạp. Tôi sẽ dùng ReAct khi cần tool use thật sự, không dùng chỉ để làm QA đơn giản trông "agentic" hơn.

## Problem I Care About

Naive RAG có flow cố định:

```text
retrieve -> generate
```

Nhưng nhiều task cần tương tác:

- search thêm khi evidence thiếu;
- gọi calculator;
- query database;
- mở tài liệu cụ thể;
- kiểm tra kết quả trung gian;
- dừng khi đủ evidence.

Một pipeline cố định không biểu diễn tốt các quyết định này.

## The Paper's Core Idea

ReAct dùng format xen kẽ:

```text
Thought -> Action -> Observation -> Thought -> Action -> Observation -> ...
```

Model không chỉ sinh reasoning text, mà còn chọn action để tương tác với môi trường. Observation từ tool trở thành context cho bước tiếp theo.

Trong RAG, action thường là search/retrieve. Trong agent systems rộng hơn, action có thể là API call, calculator, browser, code execution, database query.

## What Actually Matters

Bài học quan trọng là **reasoning cần được grounded bằng observation**.

Chain-of-thought-only có thể nghe hợp lý nhưng bịa facts. Tool-only không có planning rõ. ReAct kết hợp cả hai: model nêu bước tiếp theo, gọi tool, rồi cập nhật dựa trên kết quả thật.

Nhưng production không nên để action space quá rộng. Agent càng nhiều tool, càng khó kiểm soát.

## Implementation Sketch

Version tôi sẽ build cho RAG:

```text
Allowed actions:
- search(query)
- read(doc_id)
- finish(answer)
- ask_clarification(question)

Loop:
1. Decide next action from current state.
2. Validate action schema.
3. Execute tool.
4. Add observation to state.
5. Stop when enough evidence or max_steps reached.
6. Generate final answer with citations.
```

Tôi sẽ không expose raw "Thought" cho user. Tôi sẽ log internal decision trace, nhưng final response chỉ cần answer và citations.

## Production Tradeoffs

**Parsing và schema reliability** là vấn đề lớn. Action output phải structured, validate được, retry được.

**Tool errors cần được xử lý**. Search trả rỗng, database timeout, API lỗi permission, observation quá dài.

**Loop có thể runaway**. Cần max_steps, max_cost, timeout, và stop criteria.

**Security surface tăng**. Tool use mở ra prompt injection, data exfiltration, unsafe actions.

**Evaluation khó hơn**. Cần chấm final answer và trajectory.

## When I Would Use It

Tôi sẽ dùng ReAct-style loop khi:

- task cần nhiều tool;
- retrieval phải diễn ra nhiều bước;
- model cần kiểm tra observation trước khi quyết định;
- query có uncertainty cao;
- latency vài bước được chấp nhận.

Ví dụ: research assistant, troubleshooting assistant, data analyst agent, multi-source QA.

## When I Would Not Use It

Tôi sẽ không dùng ReAct cho:

- FAQ đơn giản;
- single-document QA;
- exact lookup;
- app latency thấp;
- domain chưa có tool permission model rõ;
- nơi final answer quan trọng hơn trajectory.

Trong những case này, pipeline RAG rõ ràng, deterministic, dễ debug hơn.

## What I Distrust

Tôi không tin "agentic" là mặc định tốt hơn. ReAct thêm một control loop, nghĩa là thêm failure modes:

- chọn sai tool;
- query sai;
- đọc observation sai;
- lặp vô ích;
- dừng quá sớm;
- tốn chi phí không cần thiết.

Tôi cũng không muốn dùng free-form action text. Production agent cần typed actions và validation.

## Experiment I Would Run

Tôi sẽ so:

```text
static RAG
RAG + query rewrite
iterative retrieval
ReAct with search only
ReAct with search + read + calculator
```

Metrics:

- task success;
- answer correctness;
- citation support;
- tool-call count;
- invalid action rate;
- loop timeout rate;
- latency;
- cost/query.

Nếu ReAct chỉ tăng cost mà không tăng success trên task cần tool, không nên dùng.

## Takeaway

ReAct là pattern cho controlled tool use, không phải decoration.

Điểm cần nhớ:

- dùng khi task cần action thật;
- giới hạn action space;
- validate schema;
- có max_steps và budget;
- chấm trajectory, không chỉ final answer;
- static RAG vẫn là baseline cần vượt.
